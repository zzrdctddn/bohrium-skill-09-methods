# RDMW 方法细则与反例库

## 四机制关系
RDMW 的四个机制对应从"材料"到"可复做章节"的四道关卡：写得全保证不漏要素，写得准保证不造假，做得着保证能复现，说得住保证诚实。缺任一关，章节都不可用于复核。

## 写得全：六要素最小集
1. **方法步骤**：有序步骤序列，每步含输入、操作、输出、判断条件；多步操作不得压成一句。
2. **实验设置**：训练/验证/测试分别描述，含硬件、软件版本、随机种子、重复次数；条件不得串台。
3. **参数**：名称、取值、单位、作用对象、来源、来源位置；正文数值逐一对应。
4. **数据集与划分**：名称、版本、规模、预处理、划分比例与随机方式、各子集用途。
5. **对照实验**：基线对象及版本、是否同预算、评价指标与统计方式。
6. **复现与限制**：复现清单 + 限制落到具体失效场景。

任何要素缺材料，写 `missing_element` 并追问，不以"常规做法"补写。

## 写得准：参数来源优先级
配置/日志/代码里能查到的，按以下优先级取值并标注冲突：
1. 最终实验运行日志（实际执行值）；
2. 与日志匹配的配置文件；
3. 代码默认值（仅当无运行记录时，标 `code_default`）；
4. 作者口头/文字确认（标 `author_confirmed`）。
任何"为了行文合理"生成的数值都属编造，必须拦截。配置与日志冲突时并列展示，不擅自择一。

## 做得着：可复现清单六项
代码版本（含 commit）、环境与依赖版本、随机种子、完整运行命令、数据获取方式、硬件与运行环境。每项须来自材料；缺失写 `missing` 并进 `human_review_items`。命令应可原样复制执行，不省略关键参数。

## 说得住：限制落地句式
- 禁止："仍有提升空间""未来可进一步研究""存在一定局限"。
- 要求："当 [具体条件] 时，方法因 [具体原因] 失效，表现为 [具体现象]，适用范围限定为 [条件]"。
- 缺口转追问：把"未说明 X"改写成"请确认 X 的取值/版本/来源（影响 Y 的复现）"。

## 反例库
| 反例 | 为什么错 | 改法 |
|---|---|---|
| 把数据加载、归一化、训练三步压成一句 | 步骤不可执行、判断条件丢失 | 拆成 S1/S2/S3，每步写输入输出与条件 |
| 正文写"学习率 0.001"但配置为 1e-4 | 数值与来源不一致 | 以日志/配置为准，溯源表记录并改正文 |
| 配置与日志不一致时选看起来合理的那个 | 擅自择一，掩盖冲突 | 并列标 `conflict`，交作者裁定 |
| 数据集只写 "ImageNet" 不写版本与划分 | 无法复现 | 补版本、规模、预处理、划分比例与随机方式 |
| 与基线比较但预算不同 | 不可比，结论无效 | 标 `not_comparable`，降级为描述性对照 |
| 复现命令省略关键参数 | 他人照做失败 | 给完整命令，缺项标 `missing` |
| 限制写"未来可进一步研究" | 套话，无失效场景 | 落到"当 X 条件时因 Y 失效" |
| 材料无记录却补一组超参数 | 编造，损害可复现 | 拒绝并转成追问，进 `human_review_items` |
| 训练/评测条件混在一段 | 条件串台 | 分设训练/验证/测试三段分别描述 |

## 抽取与核对分离
抽取阶段只管把材料变成结构化要素与成稿；抽取完成后以"审阅者"身份独立执行 `checklist.md`，逐项验证齐全度、溯源、条件一致性与限制落地，必要时改稿并写 `change_log`。两遍不可合并，避免"自己写自己过"。
