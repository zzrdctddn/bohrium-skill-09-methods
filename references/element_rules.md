# 六要素定义与可比性规则

## 要素一：方法步骤
- 有序编号（S1…Sn），每步四栏：输入 / 操作 / 输出 / 判断条件。
- "判断条件"是分支依据（如"若损失连续 5 轮不降则停止"），必须来自材料；无分支写"无"。
- 禁止把"加载→归一化→增强→训练"压成一句。

## 要素二：实验设置
- 训练、验证、测试分三段写；每段注明数据子集、用途、评测频率。
- 记录硬件（GPU 型号/数量、CPU、内存）、软件（OS、语言/框架版本）、随机种子、重复次数与取值方式（如 3 次取均值±标准差）。

## 要素三：参数
- 字段：名称、取值、单位、作用对象（如"仅编码器"/"全局"）、来源、来源位置、状态。
- 来源状态枚举：`sourced`（配置/日志/代码查得）、`code_default`（代码默认且无运行记录）、`author_confirmed`（作者确认）、`conflict`（多处不一致）、`unsourced`（无来源，须追问）。

## 要素四：数据集与划分
- 字段：名称、版本（含获取日期/快照号）、规模、预处理步骤、划分比例、随机方式与种子、各子集用途。
- 常见失效：只写数据集名不写版本；划分比例与随机方式缺失；验证集参与训练（数据泄漏）——发现泄漏须标 `conflict` 并追问。

## 要素五：对照实验
- 字段：基线对象及版本、对照条件（是否同预算/同数据/同指标）、评价指标、统计方式（均值/方差/显著性检验）。
- `comparable=true` 须满足：同数据集与划分、同预算或明确说明预算差异、同评价指标、同统计方式。否则 `not_comparable`，结论降级为描述性。

## 要素六：复现与限制
- 复现清单见 `reproducibility_rules.md`。
- 限制须落到具体失效场景，见 `method.md` 的"限制落地句式"。

## 数值纪律
正文每个数值（参数、结果、比例、次数）必须能在溯源表或材料定位中找到；找不到则删除或标 `unsourced` 并追问，绝不补造。benchmark 分数不得虚构，未提供则不写。
